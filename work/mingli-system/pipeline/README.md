# 公开样本验证管线

本目录是 1000万人公开样本验证工程的管线设计区。

## 阶段

1. `source_intake`：登记来源与许可。
2. `identity_resolution`：公开人物去重与外部 ID 合并。
3. `birth_normalization`：出生资料标准化。
4. `event_extraction`：公开事件抽取。
5. `chart_calculation`：按资料精度计算三柱或四柱。
6. `rule_evaluation`：将理论规则与已发生事件比对。
7. `bias_matrix`：生成规则偏差矩阵。
8. `report_feedback`：把偏差矩阵写回报告引擎。

## 重要原则

- 不保存普通人隐私。
- 不抓取不允许复用的数据。
- 不把低精度样本用于高精度断事。
- 不把模型验证结果写成确定命运结论。

## Wikidata 首批查询思路

首批只取公开结构化字段：

- QID
- 姓名
- 出生日期
- 死亡日期
- 出生地
- 职业
- 国籍

不要在第一批抓长文本。先做结构化索引，再逐步补事件。

## 当前种子策略

在线 SPARQL 全库扫描在本地测试中容易超时，因此首批使用固定 QID `VALUES` 查询，先验证导入管线。后续扩展到百万、千万级时，应优先采用：

- Wikidata dump 批处理。
- 按 QID 区间分页。
- 按出生年份窗口分页。
- 失败可恢复的 import batch。

不要用一个超大在线 SPARQL 查询直接拉取海量数据。
