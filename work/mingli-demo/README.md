# 参天命理综合研判 Demo

一个本地运行的命理报告应用。用户录入出生资料后，服务端完成农历换算、四柱排盘、真太阳时校验、资料质量分级与报告生成；查询保存在本机，支持搜索、回看、版本复用和删除。

## 启动

```powershell
cd work/mingli-demo
python -m pip install -r requirements.txt
python server.py --port 8765
```

浏览器打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。页面必须通过本地服务访问，不能直接双击 `index.html`。

## 公网移动端部署

仓库根目录已提供 `render.yaml`，可在 Render 连接 GitHub 仓库后直接部署为 Web Service。Render 会从 `work/mingli-demo` 安装依赖，并以 `python server.py --host 0.0.0.0` 启动；服务端会自动读取云平台注入的 `PORT` 环境变量。

部署步骤：

1. 登录 Render，选择 New Blueprint 或 New Web Service。
2. 连接 GitHub 仓库 `dengsan721-prog/cantian-mingli-report`。
3. 选择分支 `codex/precision-validation-foundation`。
4. 确认服务名 `cantian-mingli-report`，部署完成后打开 Render 给出的 `https://...onrender.com` 地址。

生成报告依赖 Python 后端接口，不能只用 GitHub Pages 作为完整产品链接。免费实例首次打开可能需要等待冷启动。当前查询记录使用本地 SQLite 文件，云端实例重建或重新部署时记录可能丢失；需要长期保存时应改接托管数据库。

## 数据记录

- 查询记录保存在 `data/demo_records.db`。
- 数据库目录已加入 `.gitignore`，不会随代码提交。
- 每条记录保存原始输入、排盘结果、资料等级、校时候选和完整报告。
- 相同资料与相同模型版本使用稳定指纹复用已有报告，不重复堆积记录。
- 左侧可按姓名或出生地搜索历史记录。

## 精度规则

- 农历日期按当年真实月份、闰月与大小月校验后，再换算为阳历。
- 内置地点命中时自动补齐经纬度和时区；未命中时保留人工精度设置。
- 有经度和 IANA 时区时，生成真太阳时校验结果。
- 出生时刻缺失时只生成三柱，不虚构时柱。
- 无时辰但具备至少 5 项、3 类人生事件时，按校准集生成实验性结构匹配分，并以留出事件复核；匹配分不是概率，也不自动选定时辰。
- 报告提供纲要、精读、全文三种阅读层级，并保留结构化判断依据和计算底稿。
- L1-L4 资料等级决定报告可以表达的上限，缺失项会在“专家质询与缺口”中列明。

脚本只读公开人物数据库，从1920至2007年、缓存标注日期精确到日且带 Wikidata 来源链接的记录形成候选池。先冻结随机顺序，再检查来源的实际日期精度、公历标记、冲突与日期匹配，仅按资料资格取前1000人。服务繁忙时退避；中断后可复用逐条核验缓存，不降级为未经核验的数据。来源核验不是独立档案认证，样本也不代表总体人口。

生成前保存名单、来源、抽样池指纹与实现指纹，逐人检查改名不变、跨日期不变及未知时辰保留；不填补出生时刻，不使用已知成就，不写入用户查询记录。不提供 `--verified-cohort` 时仅做旧缓存压力测试，不能称为来源核验样本。

全量检查499500对，输出 `metrics.json`、`pairs.csv.gz`、`reports.jsonl.gz` 和高重复样本试读。精确位集合运算与原始集合交并比有等价测试，不使用近似哈希；均值、P95、最高值、超标配对数、涉及人数和共同段落/判断分别披露。目录已有冻结名单时拒绝覆盖，请用新的输出目录；失败样本不会被静默替换。
